# 调研：AI 时代的 Mac 磁盘空间焦虑（2026-10）

这份文件的作用是给 molt 的产品范围留一份可追溯的依据：每条结论后面都挂着能去核对的来源，改功能优先级时先看这里，而不是凭印象重排一遍。它不描述实现，也不替代 README——README 回答「怎么用」，这里回答「为什么做成这样」。

目标人群：AI 工具普及后硬盘不够用的人。两种人都在里面——懂电脑的开发者和不懂电脑的普通用户，后者尤其是不想扩容、也不想买外置硬盘的 Mac 用户。

调研方式是公开资料检索（Reddit 真实用户帖、Apple 官方支持文档、厂商定价页、中文社区搜索结果），不是推测。结论只保留能对应到具体证据的部分。

## 一、真实痛点

**1. 空间去哪了，用户不知道。** macOS 把缓存、日志、开发产物、AI 工具会话全塞进一个叫 System Data 的兜底分类里，Apple 官方文档（support.apple.com/102624，2026-10-16 更新）只说这是「不属于其他任何分类的文件」。第三方测评给开发机的估算是这个桶通常 80–200 GB（cleanmydev.com, 2026-05）。用户打开存储设置只看到一个巨大的灰条。

**2. 大头是新工具，不是系统垃圾。** 一个 256 GB MacBook 的用户实测（r/SideProject, 2026-03-18）：Xcode DerivedData 78 GB、散落的 node_modules 34 GB、Docker 镜像 29 GB、Homebrew 缓存 12 GB、pip/Cargo/Go 缓存合计约 25 GB——180 GB 全是「删了会自动重建」的东西。同类帖子（r/node, 2026-02）里 47 个 node_modules 占 38 GB。Cursor 被单独点名（r/cursor, 2026-03-28，51 分）：它默默存快照，把 Application Support 撑到 300 GB，用户连 Composer 都没用过。

**3. 知道是缓存，但不敢删。** 这是所有讨论里最稳定的一条情绪。Macworld 讲 System Data 的专文直说：删错会导致应用出错、系统不稳定，极端情况下 Mac 起不来；官方没有任何删除按钮。于是用户的默认动作是「算了，不动」。

**4. 清了没有感觉。** 移到废纸篓不释放空间、隔离区不释放空间、清掉的多是几百 MB 的小缓存——都会让用户认为工具没用。真正占几十 GB 的 target / DerivedData 恰恰被「构建产物不自动清」的安全策略排除在外。

**5. 拒绝硬件方案。** 中文社区搜索「Mac 硬盘不够用 不想买移动硬盘」时，联想词里大量是外置盘的兼容问题（NTFS 不能写、不能正常退出）；Apple 官方给出的第一条建议也是「把文件移到外部存储设备」。目标人群已经明确否掉了这条路。

## 二、现在用什么办法

| 办法 | 谁在用 | 问题 |
|---|---|---|
| `du` / `rm -rf` / Finder 手删 | 懂电脑的人 | 每次都要重来，靠记忆判断哪些能删 |
| macOS 自带存储管理 | 不懂电脑的人 | Optimize Storage 只清已看过的影片，Reduce Clutter 就是让你手动翻文件夹；对开发缓存完全无效 |
| DaisyDisk（$9.99 终身） | 两类人都有 | 只显示体积，不判断安全性——「知道大，但不知道能不能删」 |
| CleanMyMac（1 台 Mac $39.95/年，一次性 $119.95） | 不懂电脑的人 | 贵、偏系统垃圾；开发缓存和 AI 缓存不是它的重点 |
| DevCleaner / ClearDisk 这类新工具 | 开发者 | 按工具链列路径，绿/黄/红三档；免费或低价，但多数是菜单栏小工具，不看「删了会怎样」的细节 |
| 外置盘 / 云盘 | —— | 目标人群明确拒绝，或已被兼容性问题劝退 |

## 三、还没被满足的需求

1. **「删了会怎样」要具体到能下决心**，不是红黄绿三色。用户要的是「重新编译，约 3 分钟」「丢失这个文件在本地的历史版本」这种句子。
2. **后悔的余地**：删错了能拿回来。现有工具要么没有，要么叫「废纸篓」但用户不知道去哪儿找。
3. **一次点击解决，而不是先做一份盘点报告**。不懂电脑的人不会去一百多行清单里勾选；他要的是「告诉我能安全腾多少，然后帮我做掉」。
4. **对持续增长有办法**。AI 工具每天在长，手动清一次管两周。需要无人值守但只碰纯缓存。
5. **真实释放量**。要报「实际占用 / 立即释放」，而不是把硬链接和稀疏文件重复相加后的逻辑大小。
6. **空间紧张时的入口**。用户是在弹出「启动磁盘几乎已满」时才想起清理的，那时需要的是一句话结论，不是仪表盘。

## 四、付费与习惯上的信号

- DaisyDisk 的 $9.99 **一次性终身**被反复当作「值」的标杆；CleanMyMac 的 $39.95/年则长期伴随「订阅疲劳」的抱怨。Mac 小工具的心理价位偏一次性买断。
- 同时，开源免费的同类（ClearDisk、DevCleaner）已经存在，纯「按路径列表 + 删除」不值钱。愿付费的点在**判定可信 + 可还原 + 不用操心**，不是功能数量。
- 习惯上能接受的改变只有一种：把「手动清」换成「默认安全项自动清 + 大件自己决定」。要用户每次重新做一遍判断，没人会坚持。

## 五、落到 molt（ai-clear）的功能需求

### 必须有（P0）

| 需求 | 为什么 |
|---|---|
| 一句话结论 + 一个主按钮：能安全腾出多少、点一下就清 | 不懂电脑的人的唯一可走路径；现有实现的「去挑选并清理」把人推进了一百多行清单 |
| 每项三件事：这是什么、多大、删了会怎样 | 直接对应「不敢删」这条核心情绪；也是与 DaisyDisk 的分界 |
| 隔离区 + 7 天可还原 | 让「敢点」成立。已有实现，界面要把它显眼地说出来，而不是藏在第三页 |
| 覆盖 AI 工具缓存（Cursor / Claude / Codex / Ollama / HuggingFace）与 Rust/Node 构建产物 | 痛点主体就在这里；本机实扫 77.6 GB 的有代价项几乎全是 `target` |
| 三档总量分栏（可回收 / 有代价 / 受保护） | 回答「这工具到底能帮我多少」，也避免把受保护项混进「能清」里 |
| 磁盘剩余实时显示，低于阈值明确告警 | 用户是为这个数字来的 |
| 空 / 加载 / 出错 / 大量条目四种状态都有正经界面 | 扫描要几十秒、首次运行可能什么都没有；这几种状态比有数据时更常见 |

### 优先级低（P1，该有但可以后做）

| 需求 | 理由 |
|---|---|
| 按项目聚合的构建产物视图（「哪个 target 值得重编一次」） | 本机基线：可回收 1.5 GB 对 有代价 77.6 GB，真正的大件在这里。但它需要用户做技术判断，属于第二阶段 |
| 定时自动清理纯缓存 | CLI 已有，GUI 里只是开关；对「不想操心」的用户价值高，但不是打开窗口那一刻的需求 |
| 清理历史与审计 | 已有，保留即可，不作为主路径 |
| 每项判定依据（命中了哪条规则） | 增强信任，但展开才需要，不必默认铺开 |

### 明确不做（P2）

| 不做 | 理由 |
|---|---|
| 内存优化 / 一键加速 | macOS 内存由内核管，收益趋近于零；会稀释「我们只解决磁盘」的可信度 |
| 大文件扫描、重复文件、卸载器 | 竞品红海，且不属于「AI 时代缓存」这个定位 |
| 迁到外置盘 / 云 | 目标人群明确拒绝，官方建议已经失效 |
| AI 参与删除判定 | 删除不可逆，不能由概率决定；AI 最多解释「这是什么」 |
| 订阅制 | 与这个品类的付费习惯相反；一次性买断更符合预期 |

## 六、对界面设计的直接约束

1. 首页先给结论（还剩多少 / 能安全腾多少），再给动作，最后才给明细。
2. 主按钮只有一个；次按钮不超过两个。
3. 「受保护」用灰不用红，红色只留给不可撤销的操作。
4. 术语不外包：不出现 `alloc_bytes`、`inode`、`verdict` 这类词；说「实际占用」「能不能删」。
5. 每种状态都要有一句话解释「为什么这里是空的」。
